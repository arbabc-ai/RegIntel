# regintel_p1 — Phase 1 provision parser, evidence index, retrieval evaluation

Standard library only. No model, embedding, network or cloud call. Reads the corpus written by
`scripts/corpus_download.py` (`/home/arbab/projects/regintel-corpus/phase1/manifest.json`) and writes a SQLite
index outside Git and OneDrive (`/home/arbab/projects/regintel-corpus/phase1-index/regintel_p1.sqlite`).

```bash
python3 -I scripts/p1.py build                       # manifest -> SQLite (re-hashes every asset, skips mismatches)
python3 -I scripts/p1.py search "minimum CET1 ratio" --scope current -k 5
python3 -I scripts/p1.py delta "12 CFR 3.22"          # baseline vs each acquired future instrument
python3 -I scripts/p1.py eval --out results.json      # eval/phase1/questions_v0.3.json (supersedes the frozen questions.json v0.2)
python3 -m unittest discover -s tests -p "test_*.py"
```

## Layers

| Module | Role |
|---|---|
| `ecfr.py` | eCFR HTML -> one provision per anchored paragraph, definition, section, appendix item, footnote and table (own text only; parent lead text kept as retrieval context; character offsets into the decoded source) |
| `fedreg.py` | Federal Register XML -> preamble passages (heading path, printed page) and amendment units (verbatim amendatory instruction paired to the section it names, plus the section text it carries) |
| `schema.py` | `source_document`, `rulemaking`, `provision` (+FTS5), `topic`, `provision_topic`, `relationship`, `rulemaking_link` |
| `topics.json` | shared topic catalog with synonyms, per-topic source coverage (`acquired`/`partial`/`not_acquired`) and provisional assignment rules |
| `build.py` | builds the index; derives `amends`, `references`, `uses_definition`, `defines` relationships and shared-RIN candidate links |
| `search.py` | BM25 (FTS5), topic-guided, exact-citation and RRF-hybrid retrievers; lifecycle labels; `answer()` and `delta()` |
| `evaluate.py` | retrieval hit@k/MRR per retriever, deterministic delta and refusal checks, universal safety invariants |

## Rules the code enforces

- Relationships carry `review_status` (`parsed_unreviewed`, `regex_unreviewed`, `candidate_unreviewed`, `unresolved_candidate`); none is reviewed.
- `amends` comes only from an instruction's explicit targets (verb-object, "In § N,", "§ N is amended", `consisting of`, part-level forms), read outside quotation marks. Any other citation in an instruction is a `references` row, never a target. Carried section text is paired only with an instruction that targets that section (`pairing_status`: `explicit`, `multiple_instructions_same_target`, `instruction_only`, `carried_text_unpaired`, `instruction_no_explicit_target`); unpaired text and its candidate instructions stay in `unresolved_candidates` / `amends_candidate` and are listed separately from `delta()` instruments.
- An instruction-only `A.x through A.y` range records numeric membership in `amendment_range` (unreviewed), so interior sections are discoverable through `delta()` (`match: range_membership`, with `range` and the complete instruction) and exact future lookup. Only plain integer minors of one part count; any other range is `unresolved_ambiguous` and asserts nothing between its endpoints.
- `answer()` returns `partial_evidence` whenever results coexist with a matched topic whose coverage is `partial` or `not_acquired`, or when **no** catalog topic matched (gap `none_matched`, coverage `unassessed`; a lexical hit does not establish coverage). With no results it returns `missing_evidence`, still carrying the gap. `evidence_found` means every matched topic is fully acquired, or the query is citation-only and its exact lookup resolves in the requested scope and part filter. `liquidity_lcr` and `liquidity_nsfr` are `partial`: acquired Fed Part 249 does not establish coverage of the missing OCC/FDIC sources.
- Each citation in a query is resolved independently (`resolve_citations`) in the requested scope and part filter, before truncation; records are interleaved across citations so none crowds out another. An unresolved citation gets its own gap `citation:<label>` (coverage `unresolved_citation`) with a reason (`part_not_acquired`, `not_found_in_acquired_part`, `excluded_by_part_filter`, `excluded_by_requested_scope`, `excluded_by_scope_and_part_filter`, `paragraph_not_found_in_acquired_section`, `paragraph_precision_unresolved`), even when another citation resolved or an acquired topic matched. A missing paragraph is never replaced by its parent section in current scope; section-level amendment units stay discoverable but are flagged `paragraph_precision_unresolved` (paragraph precision there is an unreviewed text-pattern check of an amendment's leading designators). Every citation record states `legal_validity: not_determined`: unavailable evidence is not a finding that a citation is invalid. `evidence_found` for a citation-only query requires every citation resolved at the requested precision.
- A requested citation is read once, by one parser (`parse_query_citations`), for `citation_only`, `resolve_citations` (hence exact/hybrid and `answer`) and `delta`. Whitespace inside a complete designator (`3.1(c)( 4 )(i)`, tabs, newlines) is normalized for lookup; the record keeps `requested` (as asked) and `canonical`. An unclosed or malformed designator (`3.22(a)(999`) or one set apart by whitespace (`3.1(c)(4) (i)`, `3.22 (a)`) is never read as its own ancestor: the request is an explicit unresolved citation labelled as asked, with reason `unclosed_or_malformed_designator_suffix` or `detached_designator_suffix`, `diagnostics` (valid prefix, unread suffix, `accepted_valid_prefix: false`), a coverage gap, and no records; the section it sits in appears only as a count under `context_available`. `legal_validity` stays `not_determined`. An ordinary trailing parenthetical (`(introductory text)`) is not a suffix.
- Designator suffixes carry no length limit. `fedreg.paren_suffix` is the one reader used for requested citations and amendatory instructions: a complete `(…)` of any length extends the path, whitespace inside it normalized in a parsing view only; an unclosed one (`3.22(a)(9999999`, 6, 7, 8, 9 or 20 digits alike) or a designator-shaped fragment that is not complete never establishes its parent. In an instruction it ends the list, so `revising paragraph (a)(9999999 to read as follows:` names no `(a)`; in a request it is an explicit unresolved citation. A closed multi-word explanation glued to a path (`(a)(introductory text)`) is still ordinary explanation. Regressions group `suffix_integrity` (SI01-SI05) guards this across resolver, exact/hybrid answers and delta. Directly after a path, anything that is not a complete designator is unread unless it is a closed, unnested, multi-word explanation whose first word is not designator-shaped: a punctuation-led suffix (`(a)(-1)`) and an unclosed one (`(a)(introd and (b)`, where the later `)` belongs to something else) never establish `(a)`, in requests or instructions (SB01-SB03).
- Appendix text. A Federal Register REGTEXT can carry an appendix as a title heading (`Appendix A to Part 252—…`) followed by a direct `EXTRACT` with no SECTION wrapper. These blocks are recovered, in document order (headings, paragraphs, footnotes, tables with their notes, `* * *` elisions), as `amendment` records with `carried_text_origin=appendix_extract`, `pairing_status=appendix_text`, a null `section_no` and the `appendix` JSON column: part, letter, publisher title, `binding_status: not_determined`, passage `n of m`, source sha256/URLs, the source `EXTRACT` span and a token fingerprint of the source element. Locators are `<doc>:reg:<n>:appx-<part>-<letter>:<nnn>of<mmm>`. An instruction about an appendix as a whole (`Appendix A to part 252 is revised`, `In appendix B to part 252:`) keeps its own record (`appendix_instruction`) and targets no section and no part: `section 2.1` there is the appendix's numbering, never `§ 2.1`, and the appendix never reads as an amendment of every provision of the part. Which passages inside the appendix change stays unresolved. Direct EXTRACT blocks without an appendix title are still not recovered; `parse_stats.direct_extract_not_recovered` counts them. Regressions group `appendix_evidence` (AE01-AE07) pins this on the acquired corpus.
- Titleless section citations (`§ 3.22`). `Index.title_resolution` is the one title decision for the citation resolver and `delta()`: an explicit title is used as written; otherwise the single title with acquired evidence for the section (eCFR section or numeric range, `amends`/`amends_candidate` target, numeric amendment range) is used, falling back to the single title that has the part. A section with evidence under more than one title is `ambiguous_title`: the resolver record and `delta()` (`evidence_status: ambiguous_title`) list the candidate titles with each title's own evidence counts and return no baseline or instruments; evidence from different titles is never merged, and a missing title is never interpolated into `None CFR …`. Records and deltas carry `title_resolution`. Regressions group `titleless_delta` (TD01-TD06) pins `§ 3.22`, `§ 3.22(i)` and others against their fully qualified equivalents.
- Lists and shorthand in a request. `parse_query_citations` reads every member after a comma, semicolon, `and` or `or`. A bare section (`12 CFR 3.1, 6.1`) inherits the title of the citation before it (a titleless one stays titleless and goes through the title decision); a bare paragraph designator (`12 CFR 3.22(a) and (z)`, `3.1(c)(4)(i), (e) and (f)`) inherits section and paragraph level through the CFR hierarchy only when `fedreg.expand_shorthand` settles it. Otherwise the member is a structured unresolved expression (`ambiguous_shorthand` with `candidate_paths`, or `shorthand_without_paragraph_context`; an unclosed tail is `unclosed_or_malformed_designator_suffix`) labelled `<expr> after <previous citation>`, with a coverage gap, and members after it are not dropped. Members carry `inherited`; `requested` is the member text alone. `delta()` supports one citation and reports a multi-citation request as `evidence_status: unsupported_multi_citation` with every member listed, never the first member alone. Regressions group `query_lists` (QL01-QL07).
- Ranges in a request are unsupported and never narrowed. A section or paragraph range (`12 CFR 3.1-6.1`, `3.22(a) through (z)`, with `through`, `thru`, `to`, hyphen, en/em dash; a `through` with no readable endpoint too) is one structured unresolved expression: `malformed: unsupported_range`, `requested` is the whole expression (both endpoints), `diagnostics.range` records operator, start, end, end form, reversal and cross-part/title reading, and `interior_inferred` is false. The endpoint is not a separate citation, the resolver and exact retrieval return nothing for it, answers carry `citation:<expression>` and are never `evidence_found` (hybrid may keep contextual results as `partial_evidence`), and `delta()` reports it as unavailable with no baseline or instruments (or as `unsupported_multi_citation` next to other citations). Ordinary prose (`3.1 to the extent…`, `to 6.1 percent`) is not a range; part-level ranges are not read. Regressions group `query_ranges` (QR01-QR05).
- Malformed operands after connectors are kept. After a list separator (`,` `;` `and` `or`) a parenthesized operand that is not a complete designator — unclosed (`(z`), punctuation-led or symbol-only (`(-1)`, `(.)`, `(*)`) or a bare `(` — is its own unresolved member (`unclosed_or_malformed_designator_suffix`, label `<operand> after <previous citation>`, `requested` is the operand as written) beside the valid member, with a coverage gap; `delta()` reports `unsupported_multi_citation`. After a range operator the same operand makes the whole expression one `unsupported_range` with `end_form: malformed_endpoint`. Citations after the malformed expression are still read. Ordinary parentheticals (`(introductory text)`, `(see below)`) are not operands. Regressions group `connector_operands` (CO01-CO05).
- Part-level ranges are unsupported ranges too. `12 CFR Part 3-6`, `Part 3 through 6`, `Part 3 to 12 CFR Part 6`, `thru`, en/em dashes, reversed ranges and a `through`/`thru` with no endpoint are one `unsupported_range` expression (`end_form`: `bare_part`, `fully_qualified`, `bare_section`, `malformed_endpoint` or `missing_endpoint`), never the first part and never two independent part citations; the interior is not named. After `to`, a bare number of at most three digits ends a part range only at the end of the clause (`Part 3 to 6`, `Part 6 to 3`, `Part 3 to 6 and …`, `Part 3 to 6.`); `Part 3 to 2026`, `to 6 percent`, `to 6 banks` and `to the extent` stay a plain Part 3 citation. Regressions groups `part_ranges` (PR01-PR05) and `part_to_ranges` (PT01-PT04).
- Part lists keep every member. `12 CFR Part 3 and 6`, `Part 3, Part 6`, `Part 3 and Part 6`, `12 CFR Parts 3 and 6`, `Parts 3, 6, and 217`, with `,` `;` Oxford comma and `or`, give one citation per part. A member inherits the title of the member before it (`inherited: {kind: part, from, title_inherited}`) only from an established titled context; an explicit title (`31 CFR Part 1010`) is kept; a part listed after a titleless `§ 3.1` is an unresolved `part_without_title_context` expression. A bare number counts as a member only at the end of a clause after a part (`Part 3 and 6`, not `Part 3 and 6 banks`, `Part 3, 2026` or `to 6 percent`). Each member resolves independently, so an unacquired or filtered part has its own citation gap, also beside a topic such as CET1; `delta()` reports `unsupported_multi_citation` with every member, and plural ranges (`Parts 3 through 6`) stay one `unsupported_range`. Regressions group `part_lists` (PL01-PL05).
- Four-digit part operands are list members and range endpoints too (`31 CFR Parts 1010 and 1020`, `Part 1010 to 1020`). A bare number counts as a part below 1900 (`_bare_part_number`: up to three digits, or four digits 1000-1899); 1900-1999 could be a part or a year, so after a part it is a structured `ambiguous_part_or_year` expression (candidate `Part 1950`, no reading chosen; in a `to` range the range is unsupported with `end_form: ambiguous_part_or_year`); 2000 and later is a year (`Part 3 to 2026`, `Part 3, 2026` stay a plain Part 3), and the word `Part` always settles it (`Part 1950`). The text is read by form only; which parts are acquired is never consulted. Regressions group `four_digit_parts` (FD01-FD07).
- Ambiguous-range candidates are title-scoped. `delta()` lists the unresolved ambiguous-range candidates (reversed, cross-part or lettered `A through B` instructions) of the resolved CFR title only: identical reversed ranges under Titles 12 and 31 each reach only their own title's section, paragraph and whole-part requests; an ambiguous titleless request exposes none. A candidate is never a confirmed amendment and nothing between the endpoints is named. Regressions group `candidate_titles` (CT01-CT03; the acquired corpus holds no unresolved range, so CT01/CT02 build a small synthetic corpus).
- An explicit title in front of a section sign stays attached. `31 CFR § 3.22`, `31 CFR §§ 3.22` and `31 CFR §3.22` parse as `31 CFR 3.22` (the requested span keeps the sign) and resolve exactly like `31 CFR 3.22`; before this, the title was dropped and the request was read as titleless `§ 3.22`, which then took Title 12 (`CET1 31 CFR § 3.22` was `evidence_found` from Title 12 evidence). A title that does not have the section keeps an unresolved citation gap and never resolves through another title. Bare members after a signed head inherit its title (`31 CFR §§ 3.22, 3.12`); a section sign after a separator starts its own citation, so `12 CFR 3.1 and § 217.2(a)` still has a titleless second member, and a sign-form range endpoint inherits the start's title. Regressions group `explicit_title_sign` (ES01-ES05).
- `CFR` may be punctuated. `N C.F.R.`, `N C. F. R.`, `N c.f.r.` and `N C.F.R` are read exactly like `N CFR` in every form (signed, unsigned, paragraph, part, list, range): the requested span keeps the punctuation and the citation is canonicalized to `N CFR …`. Before this, `31 C.F.R. § 3.22` lost its title and resolved through Title 12, and the unsigned `31 C.F.R. 3.22` parsed no citation at all. Regressions group `punctuated_cfr_title` (PC01-PC04).
- An identifier that runs on with no space is never accepted as its prefix. `12 CFR 3.22.1`, `12 CFR 3.22_a`, `12 C.F.R. § 3.22.1`, `12 CFR Part 3_a`, `3.22ab` and a member such as `12 CFR 3.1 and 3.22.1` are one unresolved `unread_identifier_continuation` request: the complete text is kept, `diagnostics.unread_continuation` names the unread part (`.1`, `_a`), `valid_prefix` names what was read, and the request has its own citation gap, no exact records, no `evidence_found` and an unavailable delta (or `unsupported_multi_citation` next to valid members). A sentence-final period (`3.22.`), a lettered section (`3.22a`), paragraphs, ranges (`3.1-6.1`) and ordinary punctuation are not continuations. No legal validity is determined. Regressions group `citation_tokens` (CK01-CK05).
- A tightly joined hyphen tail is unread too. After the range reader has had its turn, a hyphen with no space on either side and identifier text after it that the range reader could not consume (`12 CFR 3.22-a`, `3.22-1`, `3.22(a)-b`, `Part 3-a`, `3.22-based`) makes the request one unresolved `unread_hyphen_tail` expression: the complete text is kept, `diagnostics.unread_continuation` is the tail (`-a`) with `unread_tail_kind: hyphen`, and it has its own citation gap, no exact records, no `evidence_found` and an unavailable delta (`unsupported_multi_citation` next to valid members). Recognised ranges (`3.1-6.1`, `Part 3-6`, `3.22(a)-(c)`), spaced prose (`3.22 - a rule`, `3.22 -a`), a trailing hyphen and a quantity range (`3.1-3.5 percent`) are unchanged. Regressions group `hyphen_tails` (HT01-HT05).
- Lists recover after an unresolved expression. An unresolved identifier (`3.22.1`), hyphen tail (`3.22-a`), part token (`Parts 3_a`, `Parts 3-a`) or unclosed designator (`3.22(a)(999`) keeps its own reason, diagnostics and citation gap, and reading then resumes at the next clear list separator (`,` `;` `and` `or`), so independently readable section or part members after it (`3.12`, `217.2`, `Part 217`) are still requested, resolved and retrievable and delta reports `unsupported_multi_citation` with every member. Title context is kept (`31 CFR 3.22.1 and 3.12` keeps title 31 for `3.12`), but paragraph shorthand after an unresolved expression inherits nothing (`ambiguous_shorthand`), and a parenthesized `(b)` inside an unclosed designator (`3.22(a)(introd and (b)`) is not a member. Regressions group `list_recovery` (LR01-LR06).
- Index-source availability. `topic_dependencies.json` declares, from each acquired topic's coverage note, the finite eCFR baseline documents it depends on (for example CET1: `ecfr:12:3`, `12:217`, `12:324`); it is separate from the keyword rules and from the declared coverage. The build records every document's outcome in `source_status` (`indexed`, `skipped_hash_or_size_mismatch`, `skipped_unsupported_format`, `empty_no_usable_provisions`, `missing_from_manifest`) and persists each unavailable dependency per topic in `topic_source_gap` with its reason (schema p1-0.7). `answer()` adds a `coverage: source_unavailable` gap listing them (also under `index.unavailable_topic_sources`) for any matched topic and makes the status `partial_evidence` when results remain, `missing_evidence` when none do, whatever other agencies' parts contribute. A usable provision is any provision other than part/subpart/authority/source/footnote headings. Citation resolution, current/future separation and delta are unchanged. This establishes source availability only, not complete provision coverage or applicability; an index built before p1-0.7 reports no dependency diagnostics, which is not the same as having verified them. Regressions group `source_coverage` (SC01-SC05).
- Designators are read whole: whitespace inside a designator (`( 1 )`, `( xiii )`, left by newlines or tabs around inline XML emphasis) is closed in a parsing view only; the stored instruction text, source bytes and hashes are unchanged. A path followed by an unclosed or whitespace-separated designator fragment (`(C)(1`, `(C) (1)`) is a valid prefix of something unread and is never accepted as a named parent; the rest of that list stays unresolved. A parenthetical that is not a designator (`(introductory text)`) does not block the path.
- Abbreviated designators in an instruction's paragraph list inherit a parent only where the CFR hierarchy (letter, digit, roman, upper, digit, roman) supports it: `(c)(5) through (7)` names (c)(5) and (c)(7) (not the interior), `(c)(4)(i), (e) and (f)` names (c)(4)(i), (e), (f) (never (c)(4)(e)), `(b)(1), (c), (d)` names (b)(1), (c), (d). Shorthand that fits two readings (`(a)(1)(i) and (v)`: roman or letter) is left unresolved, and so is every bare designator after it until a fully written path resumes the list. Section lists are consumed completely, including Oxford-comma lists (`§§ 302.1, 302.2, and 302.3` names all three); a list is not a range, and quoted lists remain references.
- A future-scope paragraph resolves only when an attributed amendatory instruction names the **complete** requested path as the object of an action (`explicit_paragraphs`, e.g. `(c)(1)`, `(a)(2)(i)`, `(i)`; quoted text and bare cross-references do not count; `(c)(5) through (7)` names its two ends, not the interior). A matching first designator, a lead of the carried text, or an ancestor never establishes a deeper path, hierarchy is not inferred from the order of carried paragraphs, and an instruction that targets several sections names no paragraph for any one of them. Otherwise the citation stays `resolved: false`, `achieved: section_only`, reason `paragraph_precision_unresolved`, with section-level amendment units still discoverable. Supporting units are listed in `future_paragraph_support`.
- A request that names a jurisdiction (names from the C3 `STATE_JURISDICTION_REGISTER.csv`, copied read-only into `jurisdictions.json` with the register's sha256 by `scripts/build_jurisdictions.py`) or states accounting intent (recognition/measurement of losses and similar, patterns in `source_requests.json`) always carries a `state_law` or `gaap_asc` `not_acquired` gap, **even when an acquired topic such as CET1 also matches**. `partial_evidence` if results exist (federal results are kept), else `missing_evidence`. The bundle's `source_requests` records what was matched and the register provenance; naming a jurisdiction asserts no state-law applicability, preemption or compliance. Federal bank names ("Federal Reserve Bank of New York") are not jurisdiction requests; abbreviations are not matched.
- `delta()` keeps the requested paragraph path. For a paragraph citation, `current_precision` and `future_precision` are reported separately (reusing `resolve_citations`). The baseline resolves only if the paragraph (or something beneath it) is in the current text; otherwise `baseline` is null and the section's baseline appears only as `section_context` (role `section_context_not_the_requested_paragraph`). Each instrument carries its own `paragraph_precision` and `role` (`paragraph_supported` or `section_context`), decided from that instrument's own units via the `explicit_paragraphs` contract; one instrument's support never establishes another's. A lettered section such as `3.4a` that is not acquired returns `evidence_status: unavailable` with a structured reason, `legal_validity: not_determined`, and no exception.
- One current-baseline lookup (`Index.current_baseline`) serves `resolve_citations`, `exact`, `answer` and `delta`. An acquired exact section is always preferred. Otherwise a numeric section inside an acquired eCFR range section (e.g. `3.5` in `3.4-3.9`) resolves to that range record, which keeps the publisher's own locator, citation, hash and dates and is labelled `match: range_section` with `range_membership` (requested section, range locator, endpoints, and a note that reserved text is acquired evidence, not an operative obligation). A range needs the same title and part, numeric ordered endpoints within one part, and the requested part filter; lettered sections never match a range, and a missing paragraph is never resolved through its section or range ancestor (reason `paragraph_not_found_in_acquired_range`). Hybrid retrieval pins the first record of every resolved citation ahead of the fused ranking so a lexical hit from elsewhere cannot crowd it out of a small k.
- Citation queries honor `scope` and `parts` in SQL before ranking and truncation; `future` returns only amendment units that explicitly amend the cited section/part, never a baseline record.
- Rulemaking state is a label computed from publisher metadata and an as-of date at query time. A proposal is never
  labelled final or current; closed comments are not finalization; a passed effective date is "operative effect
  unreviewed". `effective_on` on a proposal is not legal effect.
- `delta()` lists each future instrument separately and never merges them into one future rulebook.
- Every answer carries `applicability_status: not_assessed`. A topic match or a similarity score is evidence discovery,
  not applicability.
- Topics whose sources are not acquired (FASB ASC, state law, Call Report instructions) return `missing_evidence`, or
  `partial_evidence` with the gap reported when asked together with an acquired topic.

## Evaluation exit status

`python3 -I scripts/p1.py [--db …] [--as-of …] eval [--out report.json]` writes `--out` first, prints the report with an
explicit `Overall evaluation: PASS|FAIL` section, and exits **0 only when the overall result passes**, otherwise 1. The overall
result fails on any failed frozen delta or status check, any invalid gold matcher, any violated part filter, or any failed
check in a regression group (`delta`, `relationship_integrity`, `citation_scope`, `status`, `citation_completeness`,
`mixed_source`, `delta_precision`, `instruction_boundary`, `current_agreement`). Retrieval hit rates and MRR are
measurements; no ranking threshold is applied. Failing frozen expectations (S05, S06) are reported as failures, not waived.
The report's `overall` object lists the failing ids per category.

## Not done

No dense/neural retriever (no embedding model was available without installing packages or downloading weights), so
the "semantic" half of hybrid retrieval is the topic-catalog expansion, not vectors. The `Index.retrieve` interface and
`evaluate.RETRIEVERS` are where a vector retriever would be compared. No reranker, no relationship review, no
applicability engine, no parsing of tables into cells beyond `|`-joined rows.

**Required sections (S7-P1-REQUIRED-SECTIONS-32).** `topic_dependencies.json` (v0.2) may declare `required_sections` per topic: the sections its coverage note names inside its source parts (`cbl_ratio`: 12 CFR 3.12, 217.12, 324.12). At build, a source that is indexed but has no indexed section with that number persists a `missing_required_section` gap (`doc_key` `<document>#<section>`) in `topic_source_gap`. The matched topic then reports it as `source_unavailable` in answer coverage gaps and is never `evidence_found`. A section named for a document that is not one of the topic's sources is a build error. This checks presence of the section number only; it does not establish that the section text is complete, applicable or in force.

**Rulemaking source availability (S7-P1-RULEMAKING-SOURCE-AVAILABILITY-33).** `topic_dependencies.json` (v0.3) also declares `required_rulemaking_sources`, separately from the eCFR baseline: the Federal Register documents a topic's coverage note names as acquired (`cbl_ratio`: `fr:2026-08298`, the CBLR final rule). The build reconciles each against documents that were verified, parsed and indexed with usable provisions; a missing, hash/size-rejected, unsupported-format or empty-parser outcome is persisted in `source_status` and `topic_source_gap`. Answer coverage gaps carry `source_kind` (`ecfr_baseline` or `rulemaking`) per unavailable source and a note that names the rulemaking source accurately; a matched topic is `partial_evidence` when results remain and otherwise `missing_evidence`, whatever other instruments contribute. This establishes availability of the named document only, not complete rulemaking coverage or operative effect.

**Dependency verification (S7-P1-DEPENDENCY-VERIFICATION-34).** Schema p1-0.8. A build persists, in `index_meta`, `dependency_check_contract` (`p1-dependency-check-1`) and the exact sha256 of `topic_dependencies.json` and `topics.json` it checked. `Index` validates them on load (`dependency_verification` in every answer's `index` block). A legacy index with no dependency tables, a parent-era p1-0.7 index with no such metadata, or one with incomplete, obsolete or mismatched metadata is **unverified**: every matched acquired topic then carries a `dependencies_unverified` coverage gap naming the reason (unknown, not a confirmed missing source, which stays `source_unavailable` on a verified build), so the answer is `partial_evidence` when results remain and otherwise `missing_evidence`. Indexes are opened read-only and never edited; only a separately named fresh build establishes verification. Citation-only resolution, current/future separation and delta are unaffected.

**Unverified source diagnostics (S7-P1-UNVERIFIED-SOURCE-DIAGNOSTICS-35).** Persisted `topic_source_gap` rows are confirmed source gaps only when `dependency_verification.status` is `verified`. On an unverified index they are not promoted to `source_unavailable` gaps or to `index.unavailable_topic_sources`; they are kept as `unverified_source_observations` (`confirmed: false`, with `unverified_reason` and the verification metadata recorded in the index) inside the `dependencies_unverified` gap and in `index.unverified_topic_source_observations`. Verified degraded indexes keep their confirmed diagnostics; verified complete indexes and read-only handling are unchanged.

**Enumerated relative paragraphs (S7-P1-ENUMERATED-RELATIVE-PARAGRAPHS-39).** The governing location of a paragraph action is now the last section *location* citation (`In § …`, `Amend § …`, or an action verb followed by `§ …`) anywhere before it in the instruction.
